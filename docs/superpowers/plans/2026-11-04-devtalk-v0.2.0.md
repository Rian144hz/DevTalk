# DevTalk v0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DevTalk 0.2.0 ships four features, built in this order: Check text (correct a real work text and keep its tone), a Daily challenge with a system reminder and an optional "open at login", Speak out loud in Practice (Gemini hears the clip; only the transcript is kept) and Simulate (a role-play with the coach, by text or voice, with the system voices to listen).

**Architecture:** Every feature is a vertical slice: pure rules and schemas in `src/core` (no Electron), a handler group in main built on one shared `HandlerDeps` and one `InFlight` (cancellable coach calls), zod-validated channels, and a screen in the window. Audio is recorded in the window, sent once over IPC, handed to Gemini from memory and dropped. New local data: two append-only SQLite migrations (fluency notes, simulations) and one small `daily.json` (daily settings, the day's pick, the last notice).

**Tech Stack:** unchanged (Electron 44, React 19, TS 6, zod 4, vitest 5, Playwright 1.64). No new dependencies: `MediaRecorder`, Web Audio and `speechSynthesis` in the window; `Notification` and `app.setLoginItemSettings` in main.

**Spec:** `docs/superpowers/specs/2026-11-04-devtalk-v0.2.0-design.md` (Portuguese, binding) · Visual authority: `DESIGN.md`.

## Global Constraints

- Coach calls run only in the main process; the window never imports a provider SDK. Every new channel gets a zod schema in `INPUT_SCHEMAS`.
- What you write or say leaves the machine only for the coach you chose. Check text is never stored (no history, no database); Practice keeps only the transcript of a spoken answer; Simulate keeps only its text.
- Audio never touches the disk and is dropped after the call. Voice rooms stay unrecorded. Nobody's voice but your own is ever recorded or transcribed.
- Only the microphone is allowed. No paid API: no cloud text-to-speech, only the system voices through `speechSynthesis`.
- Security settings untouched: `CONTENT_SECURITY_POLICY`, `secureWebPreferences`, `isAppUrl`, `allowPermission`, `allowPermissionCheck` and `fakeMediaSwitches` are not edited (so playback of a recording uses Web Audio, never an `<audio>` with a `blob:` address, which the CSP blocks).
- Interface copy in simple English (B1). Colours, radii and pill buttons come only from `src/renderer/design-system/tokens.css` and DESIGN.md (sky blue, pills); no new colour literals.
- Check: type is one of Pull request description, Slack message, E-mail, Code review comment, Commit message, Other; text 1 to 2 000 characters; **Check** is Ctrl+Enter; blocked text says "This looks like a password or key. Remove it before you check the text."; the note is "Do not paste passwords, keys or private code. On the free Gemini plan, Google may use what you send to improve its models." (the second sentence only with the Gemini coach).
- Daily challenge: off by default; time HH:MM local, default 19:00; "Open DevTalk when I log in" off by default, disabled with "Only in the installed app" when `!app.isPackaged`; the notice is "Your daily challenge is ready" plus the theme, once per local day, never when the app opens after the time; the Home card is "Today's challenge" with the theme, `n-day streak` and **Start**; the streak rule does not change.
- Speak: recorded with `MediaRecorder` as `audio/webm;codecs=opus`, then converted in the window (decodeAudioData + OfflineAudioContext) to **WAV, 16 kHz mono 16-bit**, before it is sent: Gemini's documented audio types do not include WebM. At most 120 s (3.84 MB as WAV); IPC accepts at most 4 MB and 125 s; only Gemini has `capabilities.audioInput`, otherwise "Speaking needs the Gemini coach. Change it in Settings."; no pronunciation score.
- Simulate: five scenarios (Job interview, Daily stand-up with your manager, Code review discussion, Explain an incident, 1:1 with your lead); the coach's lines have up to 3 sentences; at most 8 lines from the person; **Finish** at any time; **Listen** uses the English system voices and disappears when there are none.
- Menu order: Home, Practice, Check, Simulate, Review, People, Messages, Rooms, Progress, Settings; Ctrl+1…Ctrl+9 then Ctrl+0 follow it.
- Unit tests always `npx vitest run --maxWorkers=2`; e2e `npx electron-vite build && npx playwright test` (one worker, set in `playwright.config.ts`); typecheck `npm run typecheck`.
- Branch `feat/v0.2.0` (check `git branch --show-current` before every commit). Commits end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not change the repo-local git e-mail. Do not update the agents view. Do not tag: the owner runs the tag.
- Nothing changes in `supabase/` or `website/`. SQLite migrations are append-only (`src/main/db/migrations.ts`).

## Review Focus

1. **Secrets and ordinary prose** — a pasted `sk-ant-…`, `ghp_…`, `AKIA…`, JWT or `password=hunter2` stops the check with the exact message and selects the passage; ordinary prose ("risk-free", "task-based", "desk-top", "reset your password", a lone `password=`) goes through. Tests in Task 1.
2. **Reminder at the edges** — a time the zone skips (02:30 on a spring-forward day) or repeats (01:30 on a fall-back day), 00:00 and 23:59, a timer that fires milliseconds early or minutes late after sleep, a time change after today's notice, an app opened after the time: one notice per local day, none after practice, none late. Tests in Task 3.
3. **Recordings** — silence or a dead microphone, the 120 s limit (auto-stop, audio kept), an empty clip, a clip over 4 MB or 125 s, a missing or denied microphone, leaving the screen while recording: a plain message and a way to record again, nothing sent, the microphone released. Tests in Task 4.
4. **Coach without audio** — Claude or Ollama selected (or switched after recording): Speak is disabled with the exact message, and a direct IPC call is refused before the provider is reached; the same for voice replies in Simulate. Tests in Tasks 4 and 5.
5. **A turn that fails mid-conversation** — rate limit, offline or cancel on turn 3 of 8, Finish pressed while a reply is on its way, a late reply after Finish: earlier lines stay, the failed line can be sent again, nothing is half-saved, the turn counter never moves twice. Tests in Tasks 5 and 6.
